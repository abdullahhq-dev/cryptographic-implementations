--Constant Time exponentiation function--
Here I replaced the mpz_powm function with mpz_powm_sec. GMP states that, for same-size arguments and identical machine state, it is designed to have the same execution time and cache-access patterns, independent of the values of the arguments.This provides resistance against timing/cache side-channel leakage from the modular exponentiation operation.

Since the Public key e is set as 2^16 + 1 = (10000000000000001), the modular exponentiation with e can be done with 17 multiplications which makes the encryption part significantly faster. since mpz_powm_sec is designed to have constant time execution, it is supposed to decrease the efficiency. here is the results I got replacing mpz_powm with mpz_powm_sec.

The structure of my RSA-CRT implementation is very similar to the RSA implementation provided in GMPbench. Both perform two modular exponentiations using the CRT exponents, dP and dQ, followed by CRT recombination. The main difference is the CRT convention used for recombination. GMPbench computes p−1 modq and reconstructs the result using p, whereas my implementation computes q−1 modp and reconstructs using q. These are equivalent CRT formulations and produce the same RSA result.

For a 2048-bit RSA key, GMPbench reported 724 operations/s, corresponding to approximately 1.38 ms/operation. My implementation measured 1.383 ms/operation for CRT decryption. Although the benchmark methodologies are not identical, the very close results provide a useful sanity check that my implementation has a comparable performance to the GMPbench implementation using the same underlying GMP arithmetic.
